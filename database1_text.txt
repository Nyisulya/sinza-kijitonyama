This workspace manual targets the fundamental structural block of modern relational 
database administration: schema specification, strict domain integrity enforcement via 
primary/foreign key mappings, and transactional queries (DDL and DML) inside a PostgreSQL 
environment. 
 
 
 
 
🔍 1. Introduction to Relational Databases & SQL 
A relational database organizes data into tables (relations) consisting of columns (attributes) and 
rows (tuples). Key foundational principles explored in this lab workbook include: 
 Data Definition Language (DDL): Statements used to create, alter, and destroy database 
structures (e.g., CREATE TABLE , DROP TABLE ). 
 Data Manipulation Language (DML): Statements used to insert, update, retrieve, and 
delete row instances (e.g., INSERT , SELECT , UPDATE , DELETE ). 
 Entity Integrity: Enforced by declaring a PRIMARY KEY , guaranteeing every row has a 
unique, non-null identifier. 
 Referential Integrity: Enforced by declaring a FOREIGN KEY , ensuring records in one table 
map to valid existing records in another. 
 Domain Integrity: Restricted by data types and 
CHECK constraints (e.g., preventing 
negative budgets or salaries).

-- 1. Departments Relation 
CREATE TABLE Departments ( 
DeptCode CHAR(2) PRIMARY KEY, 
DeptName VARCHAR(50) UNIQUE NOT NULL, 
Floor INTEGER CHECK (Floor >= 1 AND Floor <= 5), 
Budget DECIMAL(10,2) CHECK (Budget > 0.00) 
); 
 
 
-- 2. Staff Relation (Many-to-One with Departments) 
CREATE TABLE Staff ( 
StaffID CHAR(3) PRIMARY KEY, 
Name VARCHAR(50) NOT NULL, 
Role VARCHAR(30) CHECK (Role IN ('Senior Lecturer', 'Assistant 
Lecturer', 'Tutorial Assistant')), 
Salary DECIMAL(8,2) CHECK (Salary >= 2000.00), 
DeptCode CHAR(2), 
CONSTRAINT fk_staff_dept FOREIGN KEY (DeptCode) REFERENCES 
Departments(DeptCode) ON DELETE CASCADE ON UPDATE CASCADE 
); 
 
 
-- 3. Programmes Relation (Many-to-One with Departments)

'Bachelor', 'Master Degree')),

CONSTRAINT fk_prog_dept FOREIGN KEY (DeptCode) REFERENCES 
Departments(DeptCode) ON DELETE RESTRICT ON UPDATE CASCADE 
);
